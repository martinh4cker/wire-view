# 流畅度排查与验证

## 结论与边界

2026-11-18，在现有 Apple 芯片 Mac 与 Android 13 / MediaTek H.264 硬件解码平板上，对同一 1280×800、4 Mbps、60 fps 动态测试图做对照。发现两处独立问题：

1. USB 隧道中的回环 TCP 确认等待造成接收时间抖动。开启本连接的即时确认后，接收间隔 p95 由约 42–45 ms 降到约 18–19 ms，短时样本中超过 25 ms 的接收间隔由每 120 帧约 12 次降至 0。
2. 此设备上，MediaCodec 直接输出到 SurfaceView 时，解码回调约 60 fps，SurfaceFlinger 的视频层呈现却约 30 fps。用显式 GPU 纹理采样与 EGL 呈现替代直出后，同一视频流的系统呈现约 60 fps，帧间隔中位数约 16.67 ms、p95 约 16.7 ms。

实际新纹理更新约 58–60 fps，个别窗口略低；不能把每次绘制重复画面也当作新视频帧。平板本机 GPU 动画的呈现也约 60 fps，用户确认比原视频明显顺滑。以上证明该设备具备实际 60 帧显示能力，并将剩余问题缩到视频输出路径；尚未定位到厂商驱动内部的具体函数，不能推断所有 SurfaceView 或其他设备都有同一问题。

## 控制变量与对照

所有视频对照均使用生成的持续运动测试图，不采集、截图或保存用户桌面。保持同一设备、同一 USB 连接、同一编码参数。Mac 端持续产生约 16.7 ms 间隔的源时间戳。

| 条件 | 接收间隔 p95 | 系统呈现 | 说明 |
| --- | --- | --- | --- |
| 原视频直出 | 约 42–45 ms | 约 30 fps | 解码回调曾报告约 60 fps |
| 只补齐解码器帧率声明 | 约 43–45 ms | 约 30 fps | 输出格式由默认 30 修正为 60，未单独解决卡顿 |
| 直出加即时 TCP 确认 | 约 18–19 ms | 约 30 fps | 解决传输抖动，未解决呈现路径限制 |
| 仅换 TextureView | 仍有抖动 | 新纹理更新约 46–47 fps | 不是最终实现 |
| 即时确认 + EGL GPU 路径 | 约 19 ms | 约 60 fps | 新纹理更新约 58–60 fps |
| 平板本机 GPU 动画 | 不经 USB 或解码器 | 约 60 fps | 显示间隔约 16.67 ms，用户确认顺滑 |

提前设置呈现时间戳、改用解码器默认时间戳、只加实时运行参数等对照，没有独立消除此设备的直出限制，因此未将这些尝试当作修复结论。最终实现没有加入固定抖动缓冲，也没有降低分辨率或码率。

## 计数应如何理解

- `Cadence received`：视频帧收齐时的节奏，包含传输到达抖动。
- `Cadence decoded`：解码输出可用时的节奏。
- `Codec callbacks` / `render-callback`：解码器回调；不能据此推断用户看到了多少帧。
- `Cadence GPU-latched`：GL 线程采样到不同纹理时间戳的节奏，不计重复绘制同一纹理。
- SurfaceFlinger 视频层呈现时间：用于核对系统是否按约 16.7 ms 呈现；仍不是外部相机或光学测量的像素亮起时刻。

Android 官方说明，同一 VSYNC 内提交的多个缓冲并不都会显示，且解码渲染回调可能延迟、批量到达。因此需分别测量解码、GPU 更新和系统呈现。[缓冲区呈现 API](https://developer.android.com/reference/android/media/MediaCodec#releaseOutputBuffer(int,long))、[回调说明](https://developer.android.com/reference/android/media/MediaCodec.OnFrameRenderedListener)。

## 复现与回归

1. 构建并安装接收端；退出其他运行中的 Mac 发送端，仅连接一台授权的 USB 测试平板。
2. 运行 `bash macos/test.sh --video` 验证测试图、视频参数切换、配置恢复和自动重连。性能比较时保持持续运动，不能用静止桌面的低更新率判定掉帧。
3. 用 `adb -d logcat -s WireView:I` 分别看三个处理阶段。另用 `adb -d shell dumpsys SurfaceFlinger --list` 找本 App 的视频 SurfaceView 呈现层，对该层运行 `dumpsys SurfaceFlinger --latency`。层名需要完整引用，包含括号时也要保留 shell 引号。
4. 在测试流持续运行时，分别采样稳态、切后台后返回、再次切后台后返回。每次等待重新连接和至少几秒动态画面后再读当前呈现时间，排除旧层或停止更新的历史。

最终版的稳态和两轮前后台恢复均测到约 60 fps，呈现间隔中位数约 16.67 ms、p95 约 16.69 ms。Mac 默认自动化测试通过。真实桌面采集、其他画质档位及其他设备仍需各自验收，不能用本测试图的结果担保所有场景满帧。

90/120 保留为实验目标。此前 120 目标的回执曾积压约半秒；本轮以稳定 60 为目标，未宣称高刷问题已解决。回执延迟、GPU 合成时间、物理显示延迟和触摸响应应分别测量。
